# Lightweight AI/Data Science project kit

This kit keeps the existing nbflow notebook workflow and uses a minimal
Cookiecutter Data Science-style structure.

## One-time installation

```bash
./install.sh
```

The installer backs up the existing `nbflow.py` and global OpenCode `AGENTS.md`
before replacing them.

## Create projects

Local Git project, private by default only when GitHub is requested:

```bash
ai-project learner-segmentation
```

Create, commit, create a private GitHub repository, and push:

```bash
ai-project learner-segmentation --github
```

Create a public repository under an organization:

```bash
ai-project learner-segmentation \
  --github \
  --github-owner my-org \
  --github-public
```

Initialize the first notebook for Kaggle without pushing it yet:

```bash
ai-project learner-segmentation \
  --kaggle-ref bachgia2604/learner-segmentation \
  --kaggle-gpu NvidiaTeslaT4 \
  --kaggle-internet
```

Skip common NumPy/pandas/Matplotlib dependencies:

```bash
ai-project learner-segmentation --lean
```

Create the project without a first notebook:

```bash
ai-project learner-segmentation --no-notebook
```

## Kaggle commands

One-time initialization uses the canonical notebook:

```bash
notebook kaggle-init notebooks/<name>.ipynb --ref owner/slug
```

After editing `.ju.py`, either push from the hidden notebook:

```bash
notebook kaggle-push-current .notebook/.../<name>.ju.py
```

or push from the canonical notebook path:

```bash
notebook kaggle-push notebooks/<name>.ipynb
```

Both are retained intentionally. The `*-current` form resolves the canonical
notebook through the adjacent `meta.json`.


## Chained Kaggle notebooks

Project code remains in normal `.py` modules locally. During a Kaggle push,
nbflow creates a temporary notebook under `.notebook/.../kaggle/` and inserts a
hidden bootstrap cell containing a compressed copy of every path listed in:

```toml
[tool.nbflow]
kaggle_include = ["project_module"]
```

The canonical notebook under `notebooks/` is not modified. This is necessary
because Kaggle kernel push sends the metadata-selected notebook source rather
than arbitrary sibling `.py` files.

Use `--kernel` to attach the previous notebook output to the next stage:

```bash
notebook kaggle-init notebooks/00_prepare.ipynb \
  --ref owner/project-00-prepare \
  --dataset owner/raw-data

notebook kaggle-init notebooks/01_train.ipynb \
  --ref owner/project-01-train \
  --kernel owner/project-00-prepare \
  --gpu NvidiaTeslaT4

notebook kaggle-init notebooks/02_evaluate.ipynb \
  --ref owner/project-02-evaluate \
  --kernel owner/project-01-train
```

Push each stage only after the previous stage completes successfully:

```bash
notebook kaggle-push notebooks/00_prepare.ipynb
notebook kaggle-status notebooks/00_prepare.ipynb

notebook kaggle-push notebooks/01_train.ipynb
notebook kaggle-status notebooks/01_train.ipynb
```

Each stage writes durable artifacts under `/kaggle/working/artifacts/<stage>/`.
The next stage reads attached outputs under `/kaggle/input` using
`project_module.artifacts.find_input(...)`, rather than hard-coding the mount
folder generated by Kaggle.
